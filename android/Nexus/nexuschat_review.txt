───────────────────────────────────────────────────────
1. ARCHITECTURE OVERVIEW
───────────────────────────────────────────────────────

NexusChat is a privacy-focused Android messaging app using:
- WebView-based UI (HTML/JS/CSS) with native JS bridges
- Multiple transport layers: Tor, V2Ray, Snowflake, Meek, Obfs4
- End-to-end encryption via Double Ratchet (X3DH) + XChaCha20-Poly1305
- SMS-style SMP protocol for message relay
- Tailscale VPN integration for peer networking
- WireGuard VPN, WebRTC voice calls, BIP39 cryptocurrency wallet
- Traffic analysis countermeasures (padding, timing jitter, cover traffic)

2. CRITICAL VULNERABILITIES (must fix immediately)
───────────────────────────────────────────────────────

[C1] DoubleRatchet.kt:119 — DH failure returns zero key
     If key exchange fails, shared secret falls back to all-zero bytes.
     Attacker can send invalid public keys to force predictable key.
     → FIX: throw exception on DH failure, never use fallback

[C2] DoubleRatchet.kt:158 — Wrong parameter in skipMessageKeys
     Uses header.pn instead of header.n. Breaks out-of-order message
     decryption after DH ratchet.
     → FIX: replace header.pn with header.n

[C3] DoubleRatchet.kt:154 — pn reset to 0 instead of old n
     After DH ratchet, pn = 0 should be pn = n (old message count).
     Breaks skipMessageKeys for the next ratchet cycle.
     → FIX: preserve old n before resetting

[C4] DoubleRatchet.kt:139 — Only 4 bytes of nonce entropy
     AES-GCM IV buffer is 12 bytes but only bytes 0-3 are set.
     8 bytes remain 0x00. After 2^32 messages, nonce reuse → cipher broken.
     → FIX: fill all 12 nonce bytes

[C5] TrafficPadding.kt:108-114 — stripPadding destroys data
     For any payload > 1 cell (128 bytes), returns only first cell + 1 byte.
     Example: 150 bytes input → 256 bytes padded → 129 bytes returned.
     21 bytes of real data permanently lost.
     → FIX: completely rewrite stripPadding

[C6] BinaryDownloader.kt:22-27 — Zero hashes in KNOWN_HASHES
     SHA-256 verification passes when hash is all zeros.
     MITM can replace binaries with arbitrary code.
     → FIX: populate KNOWN_HASHES with real hashes

[C7] BinaryDownloader.kt:222 — ZIP Slip vulnerability
     entry.name.contains(targetName) allows "../" traversal.
     ZIP with entry "../../bin/malware" overwrites parent directory.
     → FIX: reject entry names containing ".." or starting with "/"

[C8] DnsOverTor.kt:81-100 — No loop detection in DNS compression
     Recursive DNS name parsing follows compression pointers infinitely.
     Malicious DNS response causes StackOverflowError.
     → FIX: add visited-pointer set with max depth limit

[C9] DnsOverTor.kt:238 — ArrayIndexOutOfBounds crash
     copyOfRange(12, data.size + 1) throws when safePos == data.size.
     → FIX: safePos = (pos + 4).coerceAtMost(data.size)

[C10] Bridges.kt:280-290 — Keystore wipe exposed to JS
     AndroidKeystore.clearAll() deletes ALL AndroidKeyStore entries.
     If JS is XSS'd, attacker wipes all credentials including app keys.
     → FIX: only delete known NexusChat entries, limit via allowlist

[C11] SmpServerService.kt:93 — SMP server on all interfaces
     ServerSocket(port) binds to 0.0.0.0. Anyone on local network
     can connect to port 5223 and interact with SMP protocol.
     → FIX: ServerSocket(port, 50, InetAddress.getByName("127.0.0.1"))

[C12] app.js + index.html — NO Content Security Policy
     No CSP meta tag. XSS vulnerabilities (below) are fully exploitable.
     → FIX: add <meta http-equiv="Content-Security-Policy">

[C13] app.js — 4 stored XSS vectors via innerHTML + onclick injection
     c.avatar (line 655, 1099), c.id (line 655, 1099), m.fileId (line 681),
     f.id (line 977) injected without escaping into innerHTML/onclick.
     → FIX: use esc() on ALL dynamic values, use setAttribute() not string

[C14] app.js:1349-1355 — Init chain has ZERO error handling
     10+ await calls with no try/catch. Any failure crashes init silently.
     App appears partially loaded with no user feedback.
     → FIX: wrap entire init in try/catch with visible error screen

[C15] app.js:196 — PIN stored in localStorage in plaintext
     Default PIN '123456' written to localStorage key 'nc_pin'.
     Readable by any script or filesystem access.
     → FIX: never write PIN to localStorage; use Android Keystore only

[C16] app.js:843 — Full config (auth tokens) in localStorage plaintext
     Tor controlPass, Tailscale authKey, SMP authToken all in cleartext.
     → FIX: encrypt config with device-derived key before localStorage

[C17] TorService.kt:244 — AUTHENTICATE without password/cookie
     Sends "AUTHENTICATE" with no credentials. Modern Tor uses
     CookieAuthentication 1 by default → auth FAILS → all control
     commands silently fail (NEWNYM, circuit status, etc.)
     → FIX: add CookieAuthentication 0 to torrc or read cookie file

[C18] app.js:848 — Prototype pollution in deepMerge
     for...in loop doesn't filter __proto__/constructor.
     XSS attacker can pollute Object.prototype via localStorage.
     → FIX: add hasOwnProperty + reject __proto__ keys

[C19] app.js:526-637 — WebSocket reconnect race condition
     Stale onclose handler sets State.wsConn = null after new
     WebSocket is created. Duplicate connections, silent disconnects.
     → FIX: use generation counter to ignore stale callbacks

3. HIGH-SEVERITY ISSUES
───────────────────────────────────────────────────────

[H1] Build: 4 missing XML resource files
     network_security_config.xml, data_extraction_rules.xml,
     backup_rules.xml, file_paths.xml referenced in manifest
     but DO NOT EXIST. Build cannot compile.
     → FIX: create all 4 files in app/src/main/res/xml/

[H2] Build: alpha libraries for encryption
     security-crypto:1.1.0-alpha06, biometric-ktx:1.2.0-alpha05
     Alpha encryption libraries = unacceptable risk for security app.
     → FIX: use stable versions

[H3] Bridges.kt:80-83 — Tor control auth without password
     Opens socket to control port, sends empty AUTHENTICATE.
     Modern Tor rejects this. ALL control commands fail silently.
     (Same root cause as C17)

[H4] Bridges.kt:203-218 — callbackFn code injection risk
     callbackFn parameter injected into evaluateJavascript string.
     If attacker controls callbackFn, arbitrary JS execution.
     → FIX: validate callbackFn against allowlist

[H5] Bridges.kt:280-290 — Concurrent KeyStore modification
     Iterates ks.aliases() while calling ks.deleteEntry().
     Undefined behavior on some KeyStore implementations.
     → FIX: collect aliases to list first, then delete

[H6] Obfs4Transport.kt:76-92 — Random bytes for missing key material
     If bridge node ID or pubkey hex is too short, random bytes
     substituted. Bridge identity cannot be verified → MITM.
     → FIX: reject short hex strings, don't pad with random

[H7] Obfs4Transport.kt:133-178 — No key confirmation in handshake
     Client doesn't prove knowledge of shared secret.
     MITM can forward handshake without detection.
     → FIX: add key confirmation step

[H8] ProtocolObfuscator.kt:64-67 — Cipher suite by hex substring
     suite.contains(it.toString(16)) matches substrings.
     TLS_ECDHE... might match wrong hex value.
     → FIX: exact match on cipher suite hex value

[H9] Bip39Wallet.kt:348-373 — Non-standard Ed25519 derivation
     Custom HMAC-SHA512 derivation not compatible with any standard.
     Wallets generated here CANNOT be restored by other software.
     → FIX: document as non-standard or use SLIP-0010

[H10] CryptoManager.kt:99-142 — No file integrity MAC
     Chunked encrypted format has per-chunk AEAD but no file-level
     integrity check. Attacker can truncate file undetected.
     → FIX: add final MAC over entire file structure

[H11] WebRtcBridge.kt:214-215 — Wrong dispose order
     audioSource.dispose() called BEFORE localStream.dispose().
     Stream holds reference to track which holds source.
     Native crash risk on some WebRTC implementations.
     → FIX: swap dispose order

[H12] TransportManager.kt:142-148 — OkHttpClient memory leak
     Creates new OkHttpClient objects every 15s health check.
     Connection pools and thread pools never released.
     → FIX: reuse clients or close them

[H13] V2RayService.kt:200-259 — JSON config via string interpolation
     Config JSON built with string concatenation. If config fields
     contain quotes, JSON is malformed.
     → FIX: use Gson to build JSON

[H14] SmpServerService.kt:310-320 — Race condition in handleAck
     CAS race: queue object replaced while another thread reading it.
     Messages inserted between get and replace can be lost.
     → FIX: use ConcurrentHashMap.compute

[H15] BootReceiver.kt:17-18 — Race condition at boot
     ErrorRecoveryManager.getInstance() called before app init.
     UninitializedPropertyAccessException if BootReceiver fires early.
     → FIX: lazy init or check NexusChatApp.instance

[H16] ChainProxy.kt:132-141 — Pipe thread leak
     t1.join(60000) waits 60s, then continues. Thread may outlive
     the connection and remain running in background.
     → FIX: interrupt threads after timeout

[H17] NexusVpnService.kt:99-125 — VPN routing fundamentally broken
     Sends raw IP packets (with IP headers) through SOCKS5 TCP.
     SOCKS5 expects TCP stream data, not raw IP packets with headers.
     Routing is non-functional.
     → FIX: extract TCP streams from IP packets

[H18] WireGuardConfig.kt:64-90 — WireGuard tunnel never started
     Config file written to disk but no system call to wg-quick.
     Tunnel is never created. Non-functional.
     → FIX: implement actual tunnel start via wg-quick

[H19] app.js — No SRI on 5 CDN scripts
     cdnjs.cloudflare.com scripts lack integrity attributes.
     Supply-chain compromise possible.
     → FIX: add integrity hashes

[H20] app.js — Decrypted messages in IndexedDB
     Message plaintext stored in IndexedDB 'chats' store.
     Any app on origin or with filesystem access reads all messages.
     → FIX: encrypt messages before IndexedDB storage

[H21] app.js — Wallet mnemonic/keys in DOM
     Mnemonic phrase, master key, BTC key, ETH key written to
     textContent. Browser extensions read these via getElementById.
     → FIX: never display full mnemonic; show truncated + copy button

[H22] app.js — Config export to clipboard leaks tokens
     exportConfig() copies Tor controlPass, Tailscale authKey,
     SMP authToken to clipboard. Clipboard persists indefinitely.
     → FIX: redact secrets in export, or show warning

[H23] app.js — Google Fonts privacy leak
     fonts.googleapis.com called from privacy-focused messaging app.
     Leaks user IP + app usage to Google.
     → FIX: self-host fonts or remove

4. MEDIUM-SEVERITY ISSUES

[M1] ProGuard: -keep class kotlin.** { *; } too broad
     Prevents R8 from shrinking/obfuscating all Kotlin runtime.
     → FIX: narrow to kotlin.Metadata + specific reflection classes

[M2] BouncyCastle outdated + deprecated artifact
     bcprov-jdk15on:1.70 → 2 years old, deprecated artifact name.
     CVE-2024-29857 (infinite loop in ASN.1) affects 1.76 and earlier.
     → FIX: bcprov-jdk18on:1.78+

[M3] Kotlin 1.9.22 → 2.0+ available
     K2 compiler, significant performance + security fixes.
     → FIX: upgrade to Kotlin 2.0+

[M4] Duplicate core-ktx dependency (lines 112 and 173)
     → FIX: remove one

[M5] Hardcoded JDK path in gradle.properties
     C:/Temp/jdk17/jdk-17.0.19+10 → breaks on other machines
     → FIX: use JAVA_HOME env var

[M6] app.js — WebRTC signaling broken on non-Android path
     Incoming SDP offers stored as undecryptable text messages.
     No code routes signaling to handleIncomingSdp().
     → FIX: connect SMP message pipeline to WebRTC handler

[M7] app.js — Unauthenticated message path writes garbled data
     When recipientPubKey is missing, message base64-encoded with
     empty nonce → receiver reads as "[encrypted]" → never shown.
     → FIX: show user error "No encryption key established"

[M8] app.js — monitorCallQuality interval never cleared
     Runs forever after each call, querying getStats() every 3s.
     → FIX: clearInterval on endCall()

[M9] app.js — ensureBinaries() makes pointless HTTP request
     fetch() to nexuschat.org/bin/status, result never used.
     Exfiltrates component names on every load.
     → FIX: remove dead code

[M10] index.html — "DEFAULT PIN: 123456" hardcoded in HTML
     Tells attacker exactly what to try first.
     → FIX: show only on first-run, or remove

[M11] index.html — onclick="openCallScreen(currentChat,...)"
     References undefined global currentChat (should be State.currentChat).
     Always uses fallback State.chats[0].
     → FIX: correct reference

[M12] SmpServerService.kt:236-256 — No rate limiting
     SMP server accepts unlimited connections/frames.
     DoS amplification vector.
     → FIX: add connection rate limiter

[M13] Bridges.kt:46 — Implicit broadcast for NEWNYM
     sendBroadcast(Intent("com.nexuschat.NEWNYM")) — any app intercepts.
     → FIX: use explicit intent with package name
